# Troubleshooting Matrix: ADK 3-Legged OAuth v2

When developing or deploying the 3-Legged OAuth flow, several common errors may appear. Use this matrix to identify and resolve them quickly.

---

| Error Code & Message | Probable Cause | Corrective Action |
| :--- | :--- | :--- |
| **`403 Forbidden`** <br>`API agentidentitycredentials.googleapis.com has not been used in project...` | The required GCP Agent Identity credentials service is disabled in the active project. | Enable the API via the Cloud Console or run: <br>`gcloud services enable agentidentitycredentials.googleapis.com` |
| **`404 Not Found`** <br>`Method not found` or `Resource not found` | 1. Versioning mismatch (e.g. calling `/v1/` instead of `/v1alpha/` for the Alpha features). <br>2. Resource path contains underscores or violates naming rules. | 1. Ensure you are targeting the `/v1alpha/` namespace for your `credentials:retrieve` and `credentials:finalize` requests. <br>2. Verify that the resource paths align with: `/authProviders/{provider}` (for V2) or `/connectors/{connector}` (for V1). |
| **`400 Bad Request`** <br>`Missing consentNonce` or `Invalid nonce` | The redirect callback reached a different container instance (stateless Cloud Run scaling) than the one that initiated the retrieve request, and the nonce was lost in transition. | Pass the `consent_nonce` to the browser client and store it in a cookie. In the callback route, fall back to reading the cookie value if the parameter is absent. See [Stateless Consent Nonce Management](stateless_consent_nonce.md). |
| **`400 Bad Request`** <br>`redirect_uri_mismatch` | The GCP Auth Broker's own callback URL (e.g., `.../oauthcallback`) does not match the **Authorized Redirect URIs** configured in the Google Cloud Console for the OAuth 2.0 Client ID. | 1. Open the [Credentials Page](https://console.cloud.google.com/apis/credentials). <br>2. Add the exact GCP Auth Broker callback URI to your Web OAuth client. <br>   * **V2 API (Recommended):** `https://agentidentitycredentials.googleapis.com/v1alpha/projects/<PROJECT_ID>/locations/<LOCATION>/authProviders/<PROVIDER_NAME>/oauthcallback` <br>   * **V1 API (Legacy):** `https://iamconnectorcredentials.googleapis.com/v1/projects/<PROJECT_ID>/locations/<LOCATION>/connectors/<PROVIDER_NAME>/oauthcallback` |
| **`Empty Response`** / <br>Stream abruptly ends after completing consent | The frontend middle-tier successfully validated the user but did not handle the "Already Authorized" flow (Case B). | Update the streaming loop to check if `/credentials:retrieve` returns a `token` instead of an `authUri`. If a token is present, immediately execute an inline stream resumption. See [examples/stream_resumption.py](../examples/stream_resumption.py). |
| **`403 Permission Denied`** <br>`Caller is not authorized...` | The Service Account of the Vertex AI Reasoning Engine or your custom proxy does not have permission to invoke the Auth Provider. | Ensure you've run the `add-iam-policy-binding` command to grant `roles/iamconnectors.user` to the Reasoning Engine's service account. See [OAuth Client Setup and Provider Config](oauth_client_setup.md). |
